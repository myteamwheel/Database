# Formula and source map

This document is the human-readable companion to `public/data-status.json -> modelProvenance`.
The publication artifact is the machine-readable source of truth for the exact implementation hashes and input versions used by a build. A semantic version names a model where one already exists; otherwise the SHA-256 fingerprint of the implementation files is the model version. No new accuracy claim follows from versioning a model.

## Publication contract

For every output family, `modelProvenance` records:

- the semantic model version when the model already has one;
- a deterministic SHA-256 over the exact implementation files;
- the SHA-256 of each implementation file;
- the relevant input-version identifiers and source-manifest fingerprint;
- the source/evidence description used by the output.

Publication verification recomputes this map from the checked-out source and input files. The implementation table identifies entry modules, not an exhaustive hand-maintained list: Node's native module parser traverses every local static import and re-export, including cycles. It compiles but never links or evaluates those modules. The sorted transitive file list and every file's hash appear under each output family. A changed deeply imported helper invalidates the status without a manual seed-list update. Malformed, missing, escaping, unpinned external or dynamic dependencies fail closed rather than emitting a partial fingerprint. The audit tool's two files and Node major version are also bound in `modelProvenance.dependencyAudit`. The runtime is pinned to Node 24 in release workflows; the parser is a build-time audit tool, not browser code. [Native module parser documentation](https://nodejs.org/docs/latest-v24.x/api/vm.html#class-vmsourcetextmodule).

If an implementation file changes without regenerating publication status, verification fails. The same happens if the embedded Grade Model version and provenance Grade Model version disagree. Team Fit explicitly binds the roster SHA-256 and snapshot date in addition to its historical source manifest; the historical G League team profiles do not thereby become verified current assignments.

## Exact parameter and policy inventory

Browser-calculated outputs are also covered: `app.js` (including `percentileMap/applyLab`, normalization, scope and CSV policies) is an audited entry in the performance and Team Fit families; `workspace.js` is bound with Team Fit for interactive similarity/profile displays. Both families hash `index.html` for default controls. Custom-score configuration is user-selected rather than fitted: up to four weighted within-cohort percentiles, shared ranks for ties, flipped percentiles for negative weights, excluded missing ingredients with weight renormalization, and explicit consent for mixed season scopes. Its selected fields/weights, league, ranking cohort and filter state are preserved in the URL. These runtime choices must accompany a reproduction; the publication hash alone cannot identify a user's custom score.

The following locations hold the authoritative coefficients/configuration and executable policies. They are version-bound by the dependency closure, source manifest and model-card inputs, rather than duplicated as numbers in this document where they could become stale.

Unresolved inputs and evaluation requirements remain in the authoritative checklist. A complete implementation fingerprint records what executed; it does not establish that the formula is statistically optimal or that every desired source exists.

The Grade Model now uses one canonical `GRADE_MODEL_VERSION = 3.4` constant. This corrects the prior metadata disagreement where the same build was labeled `3.1` in `gradeModel` and `3.3` in `provenance`, while the implementation itself identified the rebuild as v3.4.

## Exposure precision and accounting

Official season totals and precise minutes are the preferred source for per-36 lines: `36 × official stat total / precise season minutes`. Rounded displayed MPG is not a denominator when precise exposure exists. Fallback records without official totals use per-game rate times games over precise minutes; legacy records without games can use MPG, without inventing missing values.

Projection headlines use one decimal for expected games and box-score rates. `proj.accounting` retains nine-decimal rates and expected games; season totals use that precise expected-game exposure, not rounded headline games. Roster effective minutes use the same exposure divided by the NBA's 82-game schedule. Displayed lines can therefore differ by their stated rounding without disagreeing with the underlying 240-minute ledger.

`tests/independent-accounting.test.mjs` imports no production model, validation or formatting helper. It checks official actuals, pooled percentages, precise per-36 rates, forecast identities and all NBA roster aggregates. Deliberate corruptions must fail, so the audit cannot pass through an empty population or agreement between shared helpers.

## Numeric and stint identity safeguards

`scripts/lib/sources.mjs` accepts finite numbers and decimal numeric strings, not blank strings, booleans, containers, infinities or implicit coercions. Grade and custom-metric percentile ties use canonical numeric values. Invalid supplied official games/minutes fail normalization rather than becoming fabricated zero exposure. The shared numeric implementation is fingerprinted with the performance and Team Fit families.

`scripts/lib/roster.mjs` assigns historical stint teams from the queried team ID. It learns an abbreviation only from rows whose reported and queried IDs agree; team-filtered `TEAM_COUNT = 1` does not establish identity. Conflicts, unresolved teams and duplicate player/query rows fail the build. `tests/stint-identity.test.mjs` independently reconstructs all 1,376 published stint lines from the raw NBA and both G League competition-phase sources, including identity, exposure, games, rates and shooting percentages. Stint corrections can change historical team-dependent Team Fit and TULIP evidence; they do not change current NBA roster status or numerical projections.
